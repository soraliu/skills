# 主机执行政策

研究发生在用户主机，不假装存在隔离沙箱。所有命令按实际副作用分类。

## 可直接执行

- 读取文件、Git 历史、分支、remote 和 diff。
- 搜索代码、解析清单、列出依赖声明。
- 不加载项目代码的静态检查和报告校验。
- 已明确是纯查询的 GitHub API 请求。

## 必须先确认

- 安装依赖、工具或修改 shell/profile/global 配置。
- 执行 package lifecycle script、Make target、项目二进制或任意仓库脚本。
- 启动 Docker/Podman、虚拟机、数据库、浏览器或后台服务。
- 使用 `sudo`、特权容器、设备、宿主网络或写入系统目录。
- 访问云、Kubernetes、生产/共享数据库、消息队列、支付或其他外部服务。
- 读取凭证、密钥、浏览器会话、SSH agent、云配置或非项目环境变量。
- GitHub Fork/同步/push/PR 等外部写操作；用户调用本 Skill 表示同意报告工作流，但执行前仍要明确告知实际动作。
- 写入 `<workspace-root>/<repo-name>`、`<repo-name>-learning` 和报告 worktree 之外的位置。

## 禁止默认执行

- 删除、强制重置、强制 push、覆盖已有目录或用 `--no-verify` 绕过 hook。
- 对生产或共享系统做写验证。
- 将凭证、`.env`、私钥、访问令牌、用户数据或完整日志写入报告。
- 执行 `curl | sh`、远程脚本管道或来源未核实的二进制。

## 执行不可信代码

获得确认后仍采用最小权限：

- 先读清单与脚本内容，再执行最窄命令。
- 使用最小环境变量；避免向子进程传递无关 token 和云凭证。
- 优先离线、只读、临时数据库和项目官方测试。
- 设置合理超时；记录命令、退出码和脱敏摘要。
- 任何命令要求扩大权限或访问未披露服务时停止并再次确认。

用户拒绝或环境不允许时，继续静态研究，把对应结论标记为 `Claimed` 或 `Unknown/Conflict`，并将报告降级为 `PARTIAL`；不要反复施压。
