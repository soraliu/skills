# 学习画像与最终考核

## 画像访谈

完成只读快扫后，一次只问一个问题。每个问题提供一个推荐默认值及其影响；用户不回答非阻塞问题时可采用默认值并记录。

建议顺序：

1. 你能熟练阅读哪些语言/框架？默认：能读基础语法但不了解本项目框架。
2. 你对项目所在业务领域了解多少？默认：不了解领域术语。
3. 你想贡献代码、文档、测试、运维还是尚未决定？默认：先找一项低风险代码或测试贡献。
4. 你每周可投入多少时间？默认：3–5 小时。
5. 你能否安装依赖、运行容器和本地服务？默认：只运行无需特权的测试。
6. 你希望先建立全局心智模型，还是直接围绕某项功能深入？默认：先全局后纵切。

把事实与默认值分开记录到 `learner-profile.md`。不要询问年龄、身份或与学习无关的个人信息。

## 报告组织

### 新手

顺序：领域故事 → 术语 → 一个最小成功流程 → 组件地图 → 代码导航 → 失败路径 → 贡献练习。首次出现专业词时附英文，例如“依赖注入（Dependency Injection）”，并说明它在本项目解决什么问题。

### 熟练开发者

顺序：系统边界 → 依赖方向 → 关键不变量 → 运行时 → 核心路径 → 设计取舍 → 扩展点与贡献目标。基础语法只在影响设计时解释。

### 领域专家但代码新手

用领域事件和状态变化映射代码结构，突出业务规则在哪里落地、哪些规则只是外部假设，再补语言和框架导航。

### 代码专家但领域新手

先建立参与者、资金/数据/权限流和不变量，再讨论模块；避免仅按目录逐页介绍。

## 主动学习

报告采用主动回忆（Active Recall）的“解释 → 预测 → 验证 → 迁移”循环，并按 PocketFlow 教程式组织先讲抽象和主流程，再进入文件细节：

- 每章先给最小心智模型，再展开证据。
- 让读者在查看答案前预测调用方向、状态变化或失败结果。
- 提供能在固定 SHA 上执行的导航或测试练习。
- 最后让读者把同一方法迁移到一个未讲解的相邻模块。

报告内练习是自学材料，不产生 readiness 状态。

## 最终交互考核

仅在用户显式调用 `assess` 后进行。先读取 learner profile、报告 manifest 和 evidence，再进行 4 个自适应任务；一次只展示一个任务，根据回答追问，不把标准答案提前泄露。

1. **架构解释**：不用目录清单，说明主要边界、依赖方向和一个关键取舍。
2. **陌生路径追踪**：给一个报告未完整讲解的相邻入口，让用户预测它经过的组件、状态与副作用，再用源码核对。
3. **故障诊断**：给一项真实可推导的失败现象，要求提出证据顺序、最小复现和排除路径。
4. **贡献设计**：让用户为选定小改动说明修改点、测试、兼容性、回滚和 PR 验收标准。

每项按以下等级记录，不使用伪精确百分数：

- `independent`：独立给出正确模型，并能引用或找到证据。
- `prompted`：经提示后完成，但最初心智模型有缺口。
- `unsupported`：仍靠猜测，或无法设计验证。

判定：

- `LEARNER_READY`：前 3 项均为 independent，第 4 项至少 prompted。
- `CONTRIBUTOR_READY`：4 项均为 independent，贡献方案边界小、测试闭环完整且符合仓库约定。
- 其他情况：不授予状态，输出薄弱点和一组最小补练。

把结果保存为 `<repo-name>-learning/assessment-<ISO-date>.md`。考核结论是对当前学习者和 source SHA 的判断；仓库 SHA 改变后不得自动沿用。
